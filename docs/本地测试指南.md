# 本地测试指南

> 面向：拿到这份代码后想在本机跑起来、点一遍、改一行能验证的人。
> 环境：Windows + WSL2（Docker 在 WSL 里）。Linux 下把 WSL 相关步骤去掉即可。

---

## 一、最小可跑（只要后端 + 前端）

大部分功能不需要 Docker。影像走 `/static` 下的 JPG，DICOM/单点登录/LMS
这三块不可用，其余都能点。

### 1. 后端

```bash
cd backend
python -m venv .venv                     # 首次
.venv\Scripts\pip install -r requirements.txt

.venv\Scripts\python init_data.py        # 建表 + 演示账号 + 纳入 alembic 管理
.venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

接口文档 http://127.0.0.1:8000/docs

**演示账号**（`init_data.py` 里定义，仅本地用）：

| 账号 | 口令 | 角色 |
|---|---|---|
| admin | `Admin@123` | 管理员 |
| teacher | `Huiyan@123` | 带教医师 |
| student | `Huiyan@123` | 学员 |

> 已存在的库不会被覆盖，`init_data.py` 可以重复执行。
> 如果你的库是早先建的，口令可能已被改过，以实际为准。

### 2. 前端

```bash
cd frontend
npm install                              # 首次
npx vite --port 5178 --strictPort
```

打开 http://127.0.0.1:5178

> `--host 0.0.0.0` 只在需要容器回访前端时才加（如 LTI 联调）。

## 二、完整环境（含 DICOM / 单点登录 / LMS）

三个可独立启停，按需起：

```bash
# 影像归档（DICOM 阅片、SEG 金标准分割）
docker compose -f docker-compose.orthanc.yml up -d          # :8042

# 统一身份（OIDC 登录）
docker compose -f docker-compose.keycloak.yml up -d         # :8080

# 教学中台（LTI 1.3 联调）
docker compose -f deploy/docker-compose.moodle.yml up -d    # :8081
```

Moodle 首次启动要建几百张表，约 5～10 分钟。等健康检查变绿：

```bash
docker inspect --format='{{.State.Health.Status}}' huiyan-moodle
```

### 容器要能回访本机

容器里的 `127.0.0.1` 是容器自己。`backend/.env` 里配主机在 WSL 网络上的地址：

```
PUBLIC_BASE_URL=http://172.28.80.1:8000
FRONTEND_BASE_URL=http://172.28.80.1:5178
```

`172.28.80.1` 用这条查（不同机器不同）：

```bash
wsl -d Ubuntu2204 -e ip route | grep default
```

LTI 的完整联调步骤见 `deploy/moodle/README.md`。

## 三、验证改动：一条命令

```bash
python scripts/check_all.py           # 六项全跑
python scripts/check_all.py --quick   # 跳过依赖外部服务的两项
```

| 检查 | 依赖 | 挡的是什么 |
|---|---|---|
| 后端测试 | — | 逻辑回归 |
| 数据库一致性 | — | 迁移链跑不通、模型与库漂移、建库路径用错 |
| 前端类型检查 | — | **必须为 0**；孤儿代码、空值传给必填参数 |
| 前端构建 | — | 类型过了不代表能打包 |
| 阅片内核自检 | vite:5178 | 坐标算错、影像没解码 —— 这些都能通过编译 |
| PACS 对照巡检 | Orthanc | DICOM 能力静默降级 |

依赖的服务没起时对应项**跳过并标注**，不会伪装成通过。

单独跑某一项：

```bash
cd backend  && .venv\Scripts\python -m pytest tests/ -q
cd backend  && .venv\Scripts\python scripts/check_migration_chain.py
cd frontend && npx vue-tsc -p tsconfig.app.json --noEmit
cd frontend && node scripts/check_station.mjs 5178
```

> 类型检查必须带 `-p tsconfig.app.json`。根 `tsconfig.json` 是
> `files: []` 的引用式配置，`npx vue-tsc --noEmit` **什么都不检查、永远返回 0**。

## 五、改了数据库结构之后

```bash
cd backend
.venv\Scripts\python -m alembic revision -m "说明"   # 写迁移
.venv\Scripts\python -m alembic upgrade head          # 应用
.venv\Scripts\python -m alembic check                 # 必须「No new upgrade operations」
```

两条路径不要混用：

- **全新部署** → `python scripts/bootstrap_db.py`（建表 + stamp head）
  或 `python init_data.py`（同时写演示数据）
- **升级已有库** → `alembic upgrade head`

空库上直接 `upgrade` 会被拦下并提示该用哪条 —— 本项目的 `0001` 是空基线，
迁移链只做增量，建表由 ORM 完成。

改动会影响历史成绩或评分口径时，**加版本号而不是重算历史**
（参考 `scoring_mode`、`score_rule_version`）。

## 六、常见坑

**Moodle 一直 `health: starting` / `unhealthy`**
这个镜像里没有 `curl`，健康检查只能用 PHP 写；登录页返回 303 跳到对外端口，
不能跟随重定向。已在 compose 里处理，此处记录以免被再次「修坏」。

**Moodle 会话莫名丢失**
用 `localhost:8081` 访问，不要用 `127.0.0.1:8081`。Moodle 会跳转到
配置的 wwwroot，跨主机名后 Cookie 就带不过去了。

**阅片自检紧接构建后偶发失败**
dev server 正在重新预构建依赖，WebGL 拿到未就绪的模块。
`check_all.py` 已对该项重试，单独跑一次通常就好。

**Windows 上 alembic 报 UnicodeDecodeError**
`alembic.ini` 必须保持纯 ASCII —— `configparser` 按系统编码读，
中文 Windows 是 GBK。
