# 提交前检查

```bash
python scripts/check_all.py           # 全部
python scripts/check_all.py --quick   # 只跑不依赖外部服务的项
```

六项门禁：

| 检查 | 依赖 | 挡的是什么 |
|---|---|---|
| 后端测试 | — | 逻辑回归 |
| 数据库一致性 | — | 迁移链跑不通、模型与库漂移、建库路径用错 |
| 前端类型检查 | — | **必须为 0**；孤儿代码、空值传给必填参数 |
| 前端构建 | — | 类型过了不代表能打包 |
| 阅片内核自检 | vite:5178 | 坐标算错、影像没解码 —— 这些都能通过编译 |
| PACS 对照巡检 | Orthanc | DICOM 能力静默降级 |

依赖的服务没起时对应项会**跳过并标注**，不会伪装成通过。

---

## 为什么要收在一条命令里

分散在各处、要靠人记得去跑的检查等同于没有。前端类型检查攒到 48 个
错误才被清理一次，就是这么来的 —— 而其中混着真问题：一个空值被传给
声明为必填的参数，以及一批实现完整却没有任何界面调用的功能。

同理，「阅片内核自检」和「PACS 对照巡检」守的都是**能通过编译、也能通过
单元测试，但用户会直接看到**的问题：影像没解码出来、标注画错位置、
病例悄悄退回 JPG。

## 关于 CI

本仓库目前没有远程，所以先做成本地一条命令。接入 CI 时直接跑
`python scripts/check_all.py --quick` 即可（不依赖 vite / Orthanc）；
若 CI 环境能起这两个服务，去掉 `--quick` 可覆盖全部六项。

## 一个细节

阅片内核自检在紧接着 `vite build` 之后运行时会偶发失败：dev server 正在
重新预构建依赖，此时取到的模块还没就绪，WebGL 侧报
`Cannot read properties of null`。脚本对这一项做了重试。

不是掩盖失败 —— **一个会随机变红的门禁，很快就会被所有人当成噪音忽略，
那还不如没有**。真正的回归会在三次重试里稳定复现。
